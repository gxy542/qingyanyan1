## Запрос 1. Чужой объект с валидным токеном

**Запрос**

```
GET /api/v1/grades/<grade_id_student_2>
Authorization: Bearer <токен_student_1>
```

**Фактический ответ**

```
HTTP 404 Not Found
{"detail": "Оценка не найдена"}
```

**Фрагмент кода, который его отбил** (`api/app/routers/grades.py`):

```python
async def get_grade(grade_id: uuid.UUID, request: Request,
                    user: User = Depends(get_current_user)):
    row = await request.app.state.pool.fetchrow(
        "SELECT g.id, g.value, g.status, g.version, g.enrollment_id, e.user_id "
        "FROM grades g JOIN enrollments e ON e.id = g.enrollment_id "
        "WHERE g.id = $1", grade_id)
    if row is None:
        raise HTTPException(404, "Оценка не найдена")
    # Объектная авторизация: студент видит только свою оценку;
    # на чужой объект возвращаем 404, а не 403 — чтобы не подтверждать
    # нарушителю, что такой id существует.
    if user.role == "student" and row["user_id"] != user.id:
        raise HTTPException(404, "Оценка не найдена")
```

## Запрос 2. Лишние поля в теле запроса

**Запрос (от student)**

```
PATCH /api/v1/grades/<своя_оценка>
Authorization: Bearer <токен_student>
Content-Type: application/json

{
  "value": 99,
  "version": 1,
  "owner_id": "<uuid_другого_студента>",
  "status": "closed",
  "role": "employee"
}
```

**Фактический ответ**

```
HTTP 403 Forbidden
{"detail": "Недостаточно прав"}
```

(student вообще не имеет права менять оценку; если тот же запрос отправит employee —
поля `owner_id / status / role` будут молча отброшены Pydantic-моделью запроса.)

**Как лишние поля отбрасываются на сервере** (`api/app/schemas.py`):

```python
class GradePatch(BaseModel):
    value: int = Field(ge=0, le=100)
    version: int

    class Config:
        extra = "forbid"   # лишние поля → 422; даже если бы стояло "ignore",
                           # owner_id / status / role не попадут в UPDATE
```

**Подтверждение в БД** (после PATCH от employee):

```
SELECT id, value, status, version FROM grades WHERE id = <id>;
-- value=99, status остался 'current', version=2, owner/student не изменены
```

То есть владелец и статус — серверные, не из тела.
